💡 Why BuildContext?
AI coding agents (Claude Code, GitHub Copilot, Cursor, Gemini) waste tens of thousands of expensive tokens reading raw source files repeatedly. BuildContext solves this problem by traversing your codebase, identifying applications and microservices, and writing compact, pre-processed Markdown knowledge files (<app-id>.md and KB_INDEX.md).

3. Token Metrics & Budget Architecture
📊 Token Accounting & Tracking Metrics
BuildContext tracks approximate token counts (deterministic chars / 4 formula) across all generated files:
  • Per-File Front Matter Header: Every .md file includes exact token count in its YAML metadata (tokens: 2850).
  • Index Token Accounting (KB_INDEX.md): Lists approximate token cost for every application plus the suite total token sum (e.g. Total Suite Tokens: ~12,500 tokens across 4 applications).
  • Machine-Readable Metadata (suite.json): Exports full token telemetry for scripts and CI tooling.
  • Refine Report Savings (REFINE_REPORT.md): Reports exact token reduction before and after refinement (e.g., 300,000 tokens before → 35,000 tokens after: 88.3% token savings).

4. User-Customizable CATEGORIES.md Architecture
⚙️ How to Customize CATEGORIES.md
Categories are user-driven, not hardcoded. When you run BuildContext: Workspace, it generates .buildcontext/kb/CATEGORIES.md. You can open and edit this file to define your exact domain taxonomy: 
# BuildContext Category & Domain Architecture Spec
---
categories:
  - id: auth-security
    name: "Authentication & Security"
    agent: "Auth & Security AI Agent"
    keywords: ["auth", "security", "jwt", "token", "permission", "role", "secret"]
    paths: ["src/auth", "src/security"]

  - id: claims-processing
    name: "Insurance Claims Processing"
    agent: "Claims Domain AI Agent"
    keywords: ["claim", "policy", "adjudication", "coverage", "payout"]
    paths: ["src/claims", "lib/domain/claims"]
---
5. Refine Path & Multi-Agent Architecture Plan
🤖 Multi-Agent Decomposition Strategy
When you run BuildContext: Refine Path, BuildContext reads CATEGORIES.md, clusters all raw context files into your defined categories, and generates exactly 1 specialized Markdown context file per category (agent-auth-security.md, agent-claims-processing.md, etc.) inside _refined/.
6. Preserving Manual Developer Notes
🛡️ Safety & Preservation Guarantee
Any custom developer notes written under <!-- buildcontext:manual --> or inside <!-- buildcontext:keep -->...<!-- /buildcontext:keep --> are 100% preserved verbatim across all regenerations and refinement passes.
7. Frequently Asked Questions (FAQ)
❓ Can I delete raw .md files outside the _refined/ folder?
Yes! The merged agent-<category>.md files inside _refined/ contain 100% of the codebase knowledge in an ultra-compact format. When Refine Path completes, VS Code prompts you: [Replace Folder Files] to automatically replace raw files and save a backup in .buildcontext-backup/.
❓ How do AI agents inspect raw code when needed?
Every component, interface endpoint, and hotspot table row in BuildContext KB files includes clickable file links and line pointers (e.g. [server.ts](file:///c:/project/src/server.ts#L45)). When an AI agent needs actual implementation code, it clicks the link to inspect the exact lines in your workspace!
